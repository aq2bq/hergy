# hergy

[English](README.md) | 日本語

> [!NOTE]
>
> hergyは実験中のプロジェクトです。当面の間は利用方法が大きく変わる恐れがあります。互換性はまだ保証できません。

hergyは[herdr](https://github.com/herdrdev/herdr) + [gy](https://github.com/aq2bq/gy)をベースにした、不確実性の高いものづくりをAIエージェントチームで乗り切るための小さなCLIです。

hergy は、AI で楽してチームを組み、ものづくりをしたい人のための道具です。誰を、どのロールで、どのモデルで動かすかを YAML に書けば、そのチームを herdr の上に一度に立ち上げます。

## hergy は何をして、何をしないのか

hergy が持つのは、チームの編成と規律を管理、運用するだけで、Claude Code・Codex・OpenCode など各ベンダーが提供するAIエージェントハーネスはそのまま利用します。チーム内のエージェントの連携、状態確認、起動はそのままherdrを利用します。
セッション中のニーズ、論点、要求、受け入れ条件、決定などは全てgyへ記録され、利用されます。

hergy では、ユーザー自身が設定したチームのロール、規律をファイルで管理、運用し、チームの編成、組成を楽にすることを今は目指しています。


## インストール

```sh
go install github.com/aq2bq/hergy@latest

# 任意: AIエージェントが読む hergy スキルを入れる
npx skills add aq2bq/hergy
```

[herdr](https://github.com/herdrdev/herdr) と、使うエージェント CLI（`claude`、`codex`、`opencode` など）も必要です。

### hergy について伝える

以下のような文をプロンプトや AGENTS.md / CLAUDE.md へ書くなりして伝わるようにしておくと、AIエージェントは hergy のチームを起動・片付けるとき、チーム定義を書くとき、hergy が起動したチームの中で働くときに hergy スキルを読みます。

```
hergy のチームを起動・片付けるとき、チーム定義を書くとき、hergy が起動したチームの中で働くときは hergy スキルを読む。
```

## はじめかた

まずチーム定義のひな形を作ります。

```sh
hergy new myteam
```

<!-- words:new:start -->
ひな形のメンバーは lead と builder。team.yaml・agreement.md を書き出す。メンバーのロールとプロファイルは、
プロジェクトかグローバルのどちらかに今あるものから選ぶ。
人が選んでいないロールの文書とプロファイルは書かない。
どちらにもロールの文書が 1 つも無いときだけ、ひな形のロール lead・builder を
roles/ に書く。プロファイルも、どちらにも 1 つも無いときだけ claude-default を
profiles.yaml に書く。あるときは、team.yaml に書くロールとプロファイルを名指し、
次の一手を hergy validate にする。
既にあるチーム定義は上書きしない。
書く先は、git の中ならプロジェクトの .hergy/、外なら ~/.config/hergy/。
グローバルの config.yaml（version と lang）は、無いときだけ作る。
<!-- words:new:end -->

<!-- words:rule-documents:start -->
チーム定義の規則タブでは見出しから宛先・挿入位置・子見出しを含むかを選び、写す・移す。ドラッグは移動、Alt（Mac は ⌥）を押して放すとコピー、Shift（Mac は ⇧）を押してつかむと子見出しも含む。選んだ文は変えず、境目の空行だけを補う。移動は宛先から保存し、元の保存に失敗したら両方に残ったことを示す。文書を切り替えても下書きと保存先は文書ごとに保つ。欄の狭く・広くと全体の均等で幅を変える。標準幅は本文16pxで約40字、狭くした欄以外は標準幅を保つ。広い欄は2倍の伸び率で幅を分け、入らないときは横スクロールで読む。狭い画面では比較する文書を縦に並べる。4画面は幅の上限を設けず左右40px以上、420px未満では16px以上の余白。420px以上では帯の位置を保つ。フォーカスの無い入力欄の上のホイールはページを動かす。入力欄を読むときは一度押す。Ctrl（Mac は ⌘）とホイール、ピンチは拡大縮小。表示切替・読み直し・絞り込み・明暗の変更ではページを動かさず、行き先を名指す操作か結果が画面外にできる操作だけ行き先を画面内に出す。

右上で明るい・暗い・OSに合わせるを選ぶ。同じブラウザの同じホストとポートで設定を保つ。ホスト・ポート・ブラウザが違えば共有しない。保存領域を読めない・書けないときはOSに合わせて理由を示す。hergy の設定ファイルは変えない。

roles/<ロール名>.md と teams/<チーム定義名>/agreement.md は Markdown の全文。保存した文をそのまま初期プロンプトへ入れ、規則内の置換は再展開しない。名簿は短いメンバー名、先頭行の題、ロール名、herdr の連絡先、自分の印を含む。規則の矢印とロール名は解釈せず、team.yaml の turns: だけを検査する。チームの規則と共有ロールを横に並べ、各ファイルを全文の入力欄で編集する。共有ロールの保存は読む全員に及ぶ。古いファイルハッシュの保存は断る。
ロールとチームの暫定の目安は各1,200文字。チームは規則と初期プロンプトのひな形の固定文を数え、置換と生成文を除く。Unicode のコードポイントを数え、CRLF は LF として数える。超過は警告で、起動を断らない。
旧形式の YAML は hergy migrate --dry のあと hergy migrate で変換する。グローバルには --global を付ける。隣の .yaml.bak には元のバイト列を残し、除外した規則とメモも残る。有効な場所の旧 YAML は validate と初期プロンプトの生成を止める。衝突・シンボリックリンク・ハードリンクと復旧は CHANGELOG を参照する。
<!-- words:rule-documents:end -->

herdr のシェルペインで実行します。

```sh
hergy up myteam --dry
hergy up myteam
```


迷ったら `hergy cheat` か `hergy <コマンド> --help` を読んでください。

チーム定義の team.yaml は version: 1、1行の description、空でない members、turns を必須とする。team を書くならディレクトリのチーム定義名と一致させる。cwd はプロジェクトからの相対パスで既定は .。prompt は %{role_doc} と %{docs} を保つ。メンバーは name・role・profile を持ち、cwd・prompt を上書きできる。kind・args・env はプロファイルに書く。
workers は from・purpose・profile の組。目的は1人につき1つで、複数なら項目を分ける。カンマや読点を含む目的、同じメンバーと目的の重複は断る。ワーカーとの往復は workers から作り、turns に書かない。
turns は <from> -> <to> の一覧で、メンバー名か human を書く。未知の名前、自分への矢印、重複、渡し先が無いメンバーと人間、人間へ届かない構成は定義を断る。規則本文の矢印は解釈しない。
ledger は任意で、<write> by <member>[, <member>...] の一覧。gy の書き込み名か question to human を指定する。チームの GY_ACTOR に当たる書き込みが別メンバーに割り当てられていれば validate が警告する。gy を読めなければ1行で知らせる。終了コードは変えない。
ロールの文書は roles/<ロール名>.md、チームの規則は任意の teams/<チーム定義名>/agreement.md。先にロール、次にチームの規則を読む。古い最上位の agreement.yaml は読まず、残っていれば初期プロンプトの生成を止め、移す先を示す。
profiles.yaml は version: 1 と profiles を持ち、各プロファイルに kind、文字列の配列 args、文字列同士の env を書く。同じ名前は、チーム定義の置き場所にかかわらずプロジェクトを優先する。GY_ACTOR は hergy が決める。プロファイル名が kind と同じなら、モデルか設定を表す名前にするよう validate が警告する。
チーム定義の規則タブでは見出しから宛先・挿入位置・子見出しを含むかを選び、写す・移す。ドラッグは移動、Alt（Mac は ⌥）を押して放すとコピー、Shift（Mac は ⇧）を押してつかむと子見出しも含む。選んだ文は変えず、境目の空行だけを補う。移動は宛先から保存し、元の保存に失敗したら両方に残ったことを示す。文書を切り替えても下書きと保存先は文書ごとに保つ。欄の狭く・広くと全体の均等で幅を変える。標準幅は本文16pxで約40字、狭くした欄以外は標準幅を保つ。広い欄は2倍の伸び率で幅を分け、入らないときは横スクロールで読む。狭い画面では比較する文書を縦に並べる。4画面は幅の上限を設けず左右40px以上、420px未満では16px以上の余白。420px以上では帯の位置を保つ。フォーカスの無い入力欄の上のホイールはページを動かす。入力欄を読むときは一度押す。Ctrl（Mac は ⌘）とホイール、ピンチは拡大縮小。表示切替・読み直し・絞り込み・明暗の変更ではページを動かさず、行き先を名指す操作か結果が画面外にできる操作だけ行き先を画面内に出す。

右上で明るい・暗い・OSに合わせるを選ぶ。同じブラウザの同じホストとポートで設定を保つ。ホスト・ポート・ブラウザが違えば共有しない。保存領域を読めない・書けないときはOSに合わせて理由を示す。hergy の設定ファイルは変えない。

roles/<ロール名>.md と teams/<チーム定義名>/agreement.md は Markdown の全文。保存した文をそのまま初期プロンプトへ入れ、規則内の置換は再展開しない。名簿は短いメンバー名、先頭行の題、ロール名、herdr の連絡先、自分の印を含む。規則の矢印とロール名は解釈せず、team.yaml の turns: だけを検査する。チームの規則と共有ロールを横に並べ、各ファイルを全文の入力欄で編集する。共有ロールの保存は読む全員に及ぶ。古いファイルハッシュの保存は断る。
ロールとチームの暫定の目安は各1,200文字。チームは規則と初期プロンプトのひな形の固定文を数え、置換と生成文を除く。Unicode のコードポイントを数え、CRLF は LF として数える。超過は警告で、起動を断らない。
旧形式の YAML は hergy migrate --dry のあと hergy migrate で変換する。グローバルには --global を付ける。隣の .yaml.bak には元のバイト列を残し、除外した規則とメモも残る。有効な場所の旧 YAML は validate と初期プロンプトの生成を止める。衝突・シンボリックリンク・ハードリンクと復旧は CHANGELOG を参照する。

## チーム定義（team.yaml）

```yaml
version: 1
description: "このチームが想定するケース"
team: myteam
cwd: .



prompt: "…"
members:
  - name: lead
    role: lead
    profile: opus
workers:
  - from: lead
    purpose: 調査
    profile: opus
turns:
  - human -> lead
  - lead -> human
```

チーム定義は .hergy/ または ~/.config/hergy/ の teams/<チーム定義名>/ にある。チーム名は既定でチーム定義名、hergy up --as で別名を付けられる。定義を扱う up・new・show はチーム定義名を、動いているチームを扱うコマンドはチーム名を使う。チームのタブはチーム名で表示し、起動記録から元の定義を読む。hergy が名付けたエージェントかペインがタブにあればチームとして扱う。古い team:<チーム名>@<チーム定義名> の形も読む。エージェント一覧が読めないときは、この機械の起動記録にあるタブ名を使う。

## 変更を送るとき

変更を送る前に `go run ./tools/check diff` を一度実行してください。手元では upstream からの
変更に応じた速い検査を 1 分ほどで回し、変更が選ぶブラウザの歩き（spec）を名指しします
（`go run ./tools/check e2e tests/<名前>.spec.ts` でその歩きだけを実行できます）。CI は push
ごとに、ブラウザの歩きと race 検出を含む全品質ゲートを実行します。失敗した段を修正した後は、
その段だけを実行します。修正範囲が別の段に広がったときは diff を実行し直します。
検査の一覧は `go run ./tools/check -h` で確認できます。
