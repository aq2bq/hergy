# hergy

[English](README.md) | 日本語

> [!NOTE]
>
> hergyは実験中のプロジェクトです。当面の間は利用方法が大きく変わる恐れがあります。互換性はまだ保証できません。

hergyは[herdr](https://github.com/herdrdev/herdr) + [gy](https://github.com/aq2bq/gy)をベースにした、不確実性の高いものづくりをAIエージェントチームで乗り切るための小さなCLIです。

hergy は、AI で楽してチームを組み、ものづくりをしたい人のための道具です。誰を、どのロールで、どのモデルで動かすかを YAML に書けば、そのチームを herdr の上に一度に立ち上げます。

## hergy は何をして、何をしないのか

hergy が持つのは、チームの編成と規律を管理、運用するだけで、Claude Code・Codex・OpenCode など各ベンダーが提供するAIエージェントハーネスはそのまま利用します。チーム内のエージェントの連携、状態確認、起動はそのままherdrを利用します。
セッション中のニーズ、論点、要求、受け入れ条件、決定などは全てgyへ記録され、利用されます。

hergy では、ユーザー自身が設定したチームのロール、規律をファイルで管理、運用し、チームの編成、組成を楽にすることを今は目指しています。


## インストール

```sh
go install github.com/aq2bq/hergy@latest

# 任意: AIエージェントが読む hergy スキルを入れる
npx skills add aq2bq/hergy
```

[herdr](https://github.com/herdrdev/herdr) と、使うエージェント CLI（`claude`、`codex`、`opencode` など）も必要です。

### hergy について伝える

以下のような文をプロンプトや AGENTS.md / CLAUDE.md へ書くなりして伝わるようにしておくと、AIエージェントは hergy のチームを起動・片付けるとき、チーム定義を書くとき、hergy が起動したチームの中で働くときに hergy スキルを読みます。

```
hergy のチームを起動・片付けるとき、チーム定義を書くとき、hergy が起動したチームの中で働くときは hergy スキルを読む。
```

## はじめかた

lead と worker の2人チームのひな形を書き出します。

```sh
hergy new myteam        # git リポジトリの中ならプロジェクトの .hergy/、外なら ~/.config/hergy/ に書き出す
```

チームの `team.yaml` と `agreement.md`（チームの規則）ができます。メンバーのロールとプロファイルは、プロジェクトかグローバルのどちらかに今あるものから選びます。そこにあるロールの文書とプロファイルは書き直しません。どちらにもロールの文書が 1 つも無いときだけ `roles/lead.md` と `roles/builder.md` を、どちらにもプロファイルが 1 つも無いときだけ `claude-default` を `profiles.yaml` に書きます。あるときは、`team.yaml` に書くロールとプロファイルを名指し、次に `hergy validate` で確かめます。チームとロールの規則は Markdown の全文です。保存した本文をそのままエージェントに渡し、先頭行を名簿の題に使います。チーム定義の画面では、チームと共有ロールを横並びで編集できます。各文書の入力欄は一つで、1200 字を超えると警告します。旧 YAML の設定は [CHANGELOG の移行手順](CHANGELOG.md#migration-to-markdown-rules)で変換してください。

チーム定義の「規則」で「見出しだけ」に切り替えると、各見出しの ⋯ から別のチームやロールと挿入位置を選び、子見出しを含めて写す・移す操作ができます。つかむ部品を別の欄へドラッグすると移動、Alt（Mac は ⌥）を押して放すとコピー、Shift（Mac は ⇧）を押してつかむと子見出しも含めます。選んだ範囲は書き直さず、挿入する境目に空行がないときだけ補います。下書きを確認し、保存前なら元に戻せます。移動は宛先から保存し、元の保存に失敗した場合は両方に残ったことを表示します。文書名を押すと、その文書だけを読み書きできます。規則を開くと、その定義の全文書（チームの規則とメンバーが使うロールの文書）を本文16px・1行約40字の標準幅で並べます。ロールの画面も同じ標準幅です。「並べる」で並べる文書を選び直せ、「すべて表示」で全部に戻せます。文書を切り替えても未保存の編集は残り、保存対象は文書ごとに保たれます。欄の頭の「狭く」「広く」で幅を変え、横並び全体の「均等」で戻せます。 「広く」は標準の読み幅より欄を広げます。各文書の列は標準の読み幅を下回らず、「広く」の列は通常の2倍の伸び率で幅を配り、収まらない文書は説明文と横スクロールバーで案内します。狭い幅では、比較する2文書を縦に並べます。4画面の帯と本文は幅の上限を設けず、左右に40px以上の余白を残します。420px未満の狭い画面では、本文の幅を確保するため左右16px以上にします。420px以上では画面を切り替えても帯の位置は変わりません。狭い画面ではスクロールバーの領域を予約しないため、ページの長さによって帯の右側が動くことがあります。ページをスクロールするときは、入力欄の外側の余白を使えます。

画面の右上で「ライト」「ダーク」「OS に従う」を選べます。選択は同じブラウザの同じホスト・ポートに残り、4画面とプロジェクト間で共有されます。別のホスト名（localhost と127.0.0.1を含む）・ポート・ブラウザには引き継がれません。読み書きできない場合はOSの設定に従い、その理由を表示します。hergyの設定ファイルは変更しません。

herdr のシェルペインで実行します。

```sh
hergy up myteam --dry   # 起動せず、メンバーごとのプロンプトと読み込むファイルを確認
hergy up myteam         # 起動
```

メンバーは herdr では `myteam-lead`、`myteam-builder` として動きます。メンバー名の前にチーム名が自動で付くためです（下記）。

迷ったら `hergy cheat` が短いチートシートを出します（`hergy cheat --ai` はエージェント向けの全量を英語で出す）。`hergy <コマンド> --help` はそのコマンドのオプションを、コマンドごとの意味つきで出します。`hergy new --help` は書き込み先を言います。

トポロジーの編集画面でメンバーを選ぶと、今の定義から渡る文を「名簿」「連絡」「ターンを渡す相手」「ワーカーの追加」（あるときだけ）に分けて、そのまま読めます。規則の本文はこの欄に出しません。「全文と差分を読む」ボタンで「渡した文」「今の文」「差」を切り替えます。本文は省略しません。「今の文」と差の変更なし・追加の行には、トポロジー由来かロール・チームの規則かを文字の印で示します。削除行と記録の本文には由来の情報がないため、印を付けません。「渡した文」は最後に記録された本文で、操作名と時刻を表示します。反映・送り直しの変更理由の前置きは含まず、受信の確認ではありません。「今の文」は未保存の編集も含みます。動いていないメンバーや記録がない場合は、理由と今の文だけを表示します。このパネルでは保存や送り直しをしません。

## コマンド

| コマンド | 内容 |
|---|---|
| `hergy new <チーム定義>` | lead と worker の2人チームのひな形を書き出す。どちらかの置き場所に今あるロールとプロファイルは選び、書き直さない |
| `hergy up [チーム定義]` | チーム定義からチームを起動する。チーム名は `--as` で付け、既定はチーム定義名。`--dry` で herdr に触れず計画（メンバーごとのプロンプトをそのままの文）を出し、`--json` では計画を JSON で出す |
| `hergy down [チーム]` / `hergy down [ワーカー]` | 動いているチームを終了し、メンバーと、そのチームが追加したワーカーのペインを閉じる。動いているチームに無い名前は、そのワーカー（短い名前か herdr 名）として探し、そのワーカーのペインだけを閉じる。ワーカーのタブは、そのペインが最後の 1 枚だったときに閉じる。閉じたあと、チームが動いている間にできた git ワークツリー（プロジェクトのルートを除く。ワーカー 1 人を閉じたときは、そのワーカーを雇ったあとにできたもの）を枝・保存していない変更・main に入っていないコミットの数とともに、このプロジェクトの stash の数と消すコマンドを一覧にする（時刻は起動の記録から読み、ペインの作業ディレクトリがそこにあったワークツリーにはそう添える。hergy は消さない。一時文書は一覧に入れない）。`--dry` で閉じる予定を出す。チームのタブは閉じない |
| `hergy status [チーム]` | チーム名を付けると、メンバーとワーカーを1行ずつ、生きている `agent_status`（working/idle/done/blocked）、生きていなければ `動いていない`、ワーカーには `（ワーカー）` を付けて出す。最後に人間の返事待ち（`blocked`）のメンバーか、誰も動いていないかを出す。チーム名を省くと、動いているチームをすべて、チーム定義名と人数、同じ判定を付けて出す。herdr を読むだけ |
| `hergy apply [<メンバー名>…]` | 保存した定義と動いているチームを比べ、メンバーごとのずれを反映する。prompt が変わったメンバーには送り直し（会話は残る）、動いていないメンバーは起動、プロファイルが変わったメンバーは起動し直し（会話は消える）。メンバーを名指さなければ、ずれのあるメンバー全員を反映する。仕事中か許可待ちのメンバーは理由とともに残し、ほかは進める。1 人でも残れば終了コードは 1。`--dry` はメンバーごとの反映の仕方と変わったこと、チームの知らせを表示し、何も変えない |
| `hergy refresh <メンバー名>` / `--all` | 選んだメンバーを起動し直す。エージェントを終わらせ、同じペインで起動し直すので、会話は空から始まる。動いていないメンバーは、hergy が名付けたペインがシェルのままであればそこで起動し直す（別のものが動いていればエラーにし、`down` のあと `up` を促す）。ペインが無いメンバーは断り、`hergy apply` を示す。動いているチームにメンバーを足すのは反映の道だから。チーム定義を読み直すので、書き換えたプロファイル（その kind・args・prompt）が効く（`env` は効かない。下記）。メンバーは自分自身を起動し直せない。別のペインか、人間が実行する |
| `hergy reprompt <メンバー名>` / `--all` | 待機中のメンバーに初期プロンプトを送り直す。会話はそのまま。起動記録と比べて定義が変わっていれば、変わったことと「前の初期プロンプトの代わり」を前置きに付ける |
| `hergy hire <名前> --purpose X --task "…" [--from <メンバー>]` | ワーカーを別タブ（`worker:<チーム名>/<名前>`）に起動して仕事を頼む（主にメンバーが使う）。`--purpose` は、呼ぶメンバーの `workers:` が名指す目的であること。プロファイルはその組から決まる。目的の外は、呼べる目的を並べて断る。`--from` は、その目的のワーカーを持つメンバーが1人だけなら省ける |
| `hergy ls` | 使えるチーム定義と、チーム定義ごとに起動中のチーム名を一覧する |
| `hergy show <チーム定義>` | 最終的なチーム定義と、各値がどのファイルから来たかを出す |
| `hergy migrate [--dry] [--global]` | 旧 YAML の文書を明示的に変換する。隣に控えを残す。`--dry` は全対象の検査だけ、`--global` は共有設定を対象にする |
| `hergy validate` | すべての設定ファイルを検査し、壊れているものを示す。チーム定義は 1 回、ロールの文書も（それを使うチームの数だけではなく）1 回だけ検査する。続けて、チーム定義ごとの規則とひな形の文字数、ロール定義ごとの文書の文字数を出し、仮置きの基準（それぞれ 1,200 文字）を超えていれば警告する（警告は exit code を変えない） |
| `hergy serve` | アクティビティ、チーム定義（プロンプトの比較を含む）、ロール、プロファイルの画面を 127.0.0.1 で配り、URL を出してブラウザで開く。`--no-open` はブラウザを開かない。`--port` はポートの指定（既定は 8787、0 は空いているポート）。Ctrl-C で処理中の応答を待ってから止まる |
| `hergy version` | 入っている hergy のコミットと日時を出す |
| `hergy cheat` | 短いチートシートを出す。`--ai` はエージェント向けの全量を、設定を読まずに英語で出す |

どのコマンドも取るオプション: `-C <ディレクトリ>`（プロジェクトの指定）、`--lang ja`（コマンドの出力を日本語にする。既定は英語。serve が開く WebUI は、この指定にかかわらず日本語）、`--json`（`--dry` と併用し、計画を文ではなく JSON で出す）。`apply` / `refresh` / `reprompt` / `hire` は `--team` で対象のチームをチーム名で指定し、`apply` と `refresh` は `--timeout` も取ります。`up` は `--as <チーム名>` で、同じチーム定義を違うチーム名で起動できます（下記）。

`hergy apply` が、動いているチームへの定義の変更を入れる 1 つの操作です。hergy が保存した定義と、メンバーが最後に読んだ prompt を比べ、メンバーごとに反映の仕方（送り直す・起動する・起動し直す・反映できない）を決めます。人は、ずれを見て、反映するメンバーを選ぶだけです。コマンドはメンバーを名指すか、ずれのあるメンバー全員を反映します。画面は同じ計画を `GET /api/apply` で読み、`POST /api/apply` で反映します。`reprompt` と `refresh` は単独の道具として残ります。`reprompt` は初期プロンプトを送り直し（変わったことを前置きに付ける）、`refresh` はメンバーを起動し直します（固まったときなど）。`env` はペインを作ったときに決まるので、`env` を変えたあとは `hergy down` のあと `hergy up` です。反映はそれを断り、メンバーを起動し直しません。

`hergy serve` は、同じ設定を同じ読み方でブラウザに見せる画面です。URL を出すと、この機械の既定のブラウザでその URL を開きます。`--no-open` を付けると URL を出すだけで開きません。ブラウザを起動できなかったときは、URL を手で開けるように stderr に 1 行出して、画面はそのまま動き続けます。この機械のためのもので、127.0.0.1 だけで待ち受け、自分の名前でない要求を断り、書き込みは POST のうち、起動中のプロセスと、そのプロセスが描いたページだけが知るトークンを伴うものに限ります。書き換えるのは、画面が扱うファイル――ロールの文書、2 つの profiles.yaml、チーム定義の 2 つのファイル、グローバルの `config.yaml` の `projects:` だけです。

`hergy serve` は、並べたプロジェクトをまとめて扱う本部になります。グローバルの `config.yaml` の `projects:` にプロジェクトを並べる（絶対パスか `~/…`）と、並べたプロジェクトのチーム定義・ロール・プロファイルが、どのプロジェクトのものかと一緒に、どこで `hergy serve` を起動しても同じに出ます。`projects:` が無ければ、これまでどおり serve を起動したプロジェクトとグローバルの設定だけです。画面の上の［プロジェクト］から開く欄で並べる・外すができ（外しても、そのプロジェクトのファイルは変わりません）、チーム定義の「状態と操作」の列の起動のボタン（プロジェクトのチーム定義は「このプロジェクトで起動する」、グローバルのチーム定義は「プロジェクトを選んで起動する」）から並べたプロジェクトのチームを起動し、終了する で終了できます。起動の欄ではチームの名前を書け（空ならチーム定義の名前、`hergy up --as` と同じ）、herdr のワークスペースを選びます（1 つのワークスペースにチームは 1 つ）。結果は `hergy up` / `hergy down` と同じです。動いているチームが保存した定義とずれていると、帯に「反映していない変更 N」が出ます。押すと反映の欄が開き、メンバーごとの反映の仕方と変わったこと、会話が消えるかどうかが出ます。選んだメンバーを反映すると、`hergy apply` と同じ結果になります。進み具合と、起動の途中の確認は、起動のときと同じ欄に出ます。動いているチームは、エージェントが動いていなくても見つかります。チーム名のタブに `<チーム>-<メンバー>` の名前のペインがあれば、そのチームです。アクティビティ画面（`/activity`）は、人を待つ行と止まっている行の下に、動いているチームごとの札を並べます。札には図とメンバー・ワーカーの人数を載せ、チーム定義を開く、変更を反映する、チームを終了する操作を置きます。`/api/hq/` の API は同じ読みを返します。

## チーム定義と設定の置き場所

| 置き場所 | パス |
|---|---|
| グローバル | `$XDG_CONFIG_HOME/hergy/`（未設定なら `~/.config/hergy/`） |
| プロジェクト | `<プロジェクト>/.hergy/` |

- チーム定義は `teams/<チーム定義名>/team.yaml` に置きます。同名ならプロジェクトのものが優先です
- `profiles.yaml` とグローバルの `config.yaml` は設定ファイルです。`profiles.yaml` はどちらにも置けます。プロジェクトのチーム定義は、外のものの上にプロジェクトのものを重ねて読み（同名ならプロジェクトが優先）、外のチーム定義は外のものだけを読みます
- グローバルの `config.yaml` に `version: 1` と `lang: ja` を書くと、`--lang` なしでも日本語になります。無ければ `hergy new` が（その実行の表示の言語で）作り、あればそのままにします
- グローバルの `config.yaml` の `projects:` は本部に並べるプロジェクトの一覧です。絶対パスか `~/…` を書き、読むときに展開します。無ければ `hergy serve` は起動したプロジェクトを見せ、空の一覧ならグローバルの設定だけを見せます。相対パスは設定の誤りで、`hergy validate` と `hergy serve` が理由を出します
- `hergy up <チーム定義> --dry` は、メンバーごとのプロンプトと読み込むファイルを表示します

## チーム定義（team.yaml）

```yaml
version: 1              # 必須
description: "このチームが想定するケース"  # 必須。1 行。チーム定義を選ぶ・読む場面（チーム定義の一覧と画面、起動する枠、hergy show）で読む
team: myteam            # 任意。書くならチーム定義名（teams/<チーム定義名>/）と一致させる
cwd: .                  # 作業場所（プロジェクトの直下が基準）
                        # 文書を指す鍵はありません。teams/<チーム定義名>/agreement.md（このチーム）と
                        # roles/<ロール名>.md を読みます（プロジェクトの .hergy/ が先、
                        # 次に ~/.config/hergy/）
prompt: "…"             # 初期プロンプトのテンプレート（任意）。%{role_doc} と %{docs} は消せません
members:
  - name: lead            # メンバー名（短い名前）。herdr では「<チーム名>-lead」になる
    role: lead          # roles/lead.md を読む
    profile: opus       # profiles.yaml のプロファイル名。kind / args / env はそちらに書く
workers:                # 追加してよい「目的 → プロファイル」の組（プロンプトに書くだけで、強制しない）
  - from: lead          # このワーカーを追加してよいメンバー
    purpose: 調査        # ワーカーの目的
    profile: opus       # そのワーカーが使うプロファイル
turns:                  # 誰が誰にターンを渡すか（人間は human と書く）
  - human -> lead
  - lead -> human
```

### 1つのチーム定義から複数のチームを並べて起動する

`--as <チーム名>` を付けると、同じチーム定義を違うチーム名で起動できます。1つの `team.yaml` から2つのチームを並べて動かせます。`--as` を付けなければ、チーム名はチーム定義名（`teams/` の下のディレクトリ名）です。

メンバー名（`members[].name`）は短い名前（`lead`、`builder`）で書きます。hergy が起動するときにチーム名を付けるので、herdr での名前は `<チーム名>-<メンバー名>` になります。`demo` のチーム定義なら `demo-lead`、`demo-builder`、`--as dev2` なら `dev2-lead`、`dev2-builder` です。チーム名は自動で付くので、両方に `lead` がいても herdr で衝突しません。メンバー名に `%{team}` が残っていると止めます（この置換は名前では使わなくなりました）。

チーム名は `[a-z][a-z0-9_-]{0,24}` に、付けた後の `<チーム名>-<メンバー名>` は `[a-z][a-z0-9_-]{0,31}` に一致させてください。hergy は動いているチームを herdr から読み、起動の記録からチーム定義を見つけます。タブの名前はチーム名です。`down` / `apply` / `refresh` / `reprompt` / `hire` はどれも動いているチームをチーム名で指します。コマンドでメンバーを指すとき（`apply <メンバー名>`、`refresh <メンバー名>`、`reprompt <メンバー名>`、`hire --from <メンバー名>`）は、書いた短い名前を使います:

```sh
hergy up demo --as alpha            # demo のチーム定義を alpha というチーム名で起動
hergy up demo --as beta             # 同じチーム定義をもう一度 beta として起動
hergy apply --team alpha            # alpha のずれを反映する（変わったことを表示する）
hergy reprompt lead --team alpha    # alpha の lead に、会話を保ったまま送り直す
hergy down alpha                    # alpha のメンバーとワーカーだけを閉じる
hergy down alpha-bench              # ワーカー alpha-bench だけを閉じる
```

## 初期プロンプトの置換

| 置換 | 中身 |
|---|---|
| `%{team}` / `%{role}` / `%{name}` | チーム名、ロール、メンバーの名前（herdr での名前 `<チーム名>-<メンバー名>`） |
| `%{role_doc}` | ロールの文書 |
| `%{docs}` | `docs` の文書 |
| `%{roster}` | 名簿 |
| `%{herdr}` | herdr の中で動いているかの検証方法、連絡の仕方と、仲間の増やし方（`herdr agent start` ではなく `hergy hire`） |
| `%{turns}` | ターンを渡す相手（team.yaml の `turns:` から） |
| `%{workers}` | ワーカーを追加してよい目的と、そのコマンド（`workers:` がそのメンバーに1つでも書いているとき） |

既定のテンプレートは仮のものです。

## 変更を送るとき

変更を送る前に `go run ./tools/check diff` を一度実行してください。手元ではupstreamからの
変更に応じた検査を選び、CIでは全品質ゲートを実行します。失敗した段を修正した後は、
その段だけを実行します。修正範囲が別の段に広がったときはdiffを実行し直します。
検査の一覧は `go run ./tools/check -h` で確認できます。
