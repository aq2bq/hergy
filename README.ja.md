# hergy

[English](README.md) | 日本語

> [!NOTE]
>
> hergyは実験中のプロジェクトです。当面の間は利用方法が大きく変わる恐れがあります。互換性はまだ保証できません。

hergyは[herdr](https://github.com/herdrdev/herdr) + [gy](https://github.com/aq2bq/gy)をベースにした、不確実性の高い活動をAIエージェントチームで乗り切るための小さなCLIです。

hergy は、AI で楽してチームを組み、ものづくりをしたい人のための道具です。誰を、どのロールで、どのモデルで動かすかを YAML に書けば、そのチームを herdr の上に一度に立ち上げます。

## hergy は何をして、何をしないのか

hergy が持つのは、チームの編成と規律を管理、運用するだけで、Claude Code・Codex・OpenCode など各ベンダーが提供するAIエージェントハーネスはそのまま利用します。チーム内のエージェントの連携、状態確認、起動はそのままherdrを利用します。
セッション中のニーズ、論点、要求、受け入れ条件、決定などは全てgyへ記録され、利用されます。

hergy では、ユーザー自身が設定したチームのロール、規律をファイルで管理、運用し、チームの編成、組成を楽にすることを今は目指しています。


## インストール

```sh
go install github.com/aq2bq/hergy@latest

# 任意: AIエージェントが読む hergy スキルを入れる
npx skills add aq2bq/hergy
```

[herdr](https://github.com/herdrdev/herdr) と、使うエージェント CLI（`claude`、`codex`、`opencode` など）も必要です。

### hergy について伝える

以下のような文をプロンプトや AGENTS.md / CLAUDE.md へ書くなりして伝わるようにしておくと、AIエージェントは hergy のチームを起動・片付けるとき、チーム定義を書くとき、hergy が起動したチームの中で働くときに hergy スキルを読みます。

```
hergy のチームを起動・片付けるとき、チーム定義を書くとき、hergy が起動したチームの中で働くときは hergy スキルを読む。
```

## はじめかた

lead と worker の2人チームのひな形を書き出します。

```sh
hergy new myteam        # git リポジトリの中ならプロジェクトの .hergy/、外なら ~/.config/hergy/ に書き出す
```

チームの `team.yaml` と `agreement.yaml`（チームのルール）、`roles/lead.yaml` と `roles/builder.yaml` ができます。規則のファイルは YAML で、規則ごとに ID、本文、オンかオフか、オフにした日、人向けのメモを持ちます。エージェントに送られるのは、オンの規則の本文だけです。メモは送られません。

herdr のシェルペインで実行します。

```sh
hergy up myteam --dry   # 起動せず、メンバーごとのプロンプトと読み込むファイルを確認
hergy up myteam         # 起動
```

メンバーは herdr では `myteam-lead`、`myteam-builder` として動きます。メンバー名の前にチーム名が自動で付くためです（下記）。

迷ったら `hergy cheat` が短いチートシートを出します（`hergy cheat --ai` はエージェント向けの全量を英語で出す）。`hergy <コマンド> --help` はそのコマンドのオプションを、コマンドごとの意味つきで出します。`hergy new --help` は書き込み先を言います。

## コマンド

| コマンド | 内容 |
|---|---|
| `hergy new <チーム定義>` | lead と worker の2人チームのひな形を書き出す |
| `hergy up [チーム定義]` | チーム定義からチームを起動する。チーム名は `--as` で付け、既定はチーム定義名。`--dry` で herdr に触れず計画（メンバーごとのプロンプトをそのままの文）を出し、`--json` では計画を JSON で出す |
| `hergy down [チーム]` | 動いているチームのメンバーと、そのチームが追加したワーカーのペインを閉じる。`--dry` で閉じる予定を出す。タブごとは閉じない |
| `hergy status [チーム]` | チーム名を付けると、メンバーとワーカーを1行ずつ、生きている `agent_status`（working/idle/done/blocked）、生きていなければ `動いていない`、ワーカーには `（ワーカー）` を付けて出す。最後に人間の返事待ち（`blocked`）のメンバーか、誰も動いていないかを出す。チーム名を省くと、動いているチームをすべて、チーム定義名と人数、同じ判定を付けて出す。herdr を読むだけ |
| `hergy apply [<メンバー名>…]` | 保存した定義と動いているチームを比べ、メンバーごとのずれを反映する。prompt が変わったメンバーには送り直し（会話は残る）、動いていないメンバーは起動、プロファイルが変わったメンバーは起動し直し（会話は消える）。メンバーを名指さなければ、ずれのあるメンバー全員を反映する。仕事中か許可待ちのメンバーは理由とともに残し、ほかは進める。1 人でも残れば終了コードは 1。`--dry` はメンバーごとの反映の仕方と変わったことを表示し、何も変えない |
| `hergy refresh <メンバー名>` / `--all` | 選んだメンバーを起動し直す。エージェントを終わらせ、同じペインで起動し直すので、会話は空から始まる。動いていないメンバーは、hergy が名付けたペインがシェルのままであればそこで起動し直す（別のものが動いていればエラーにし、`down` のあと `up` を促す）。ペインが無いメンバーは断り、`hergy apply` を示す。動いているチームにメンバーを足すのは反映の道だから。チーム定義を読み直すので、書き換えたプロファイル（その kind・args・prompt）が効く（`env` は効かない。下記）。メンバーは自分自身を起動し直せない。別のペインか、人間が実行する |
| `hergy reprompt <メンバー名>` / `--all` | 待機中のメンバーに初期プロンプトを送り直す。会話はそのまま。起動記録と比べて定義が変わっていれば、変わったことと「前の初期プロンプトの代わり」を前置きに付ける |
| `hergy hire <名前> --purpose X --task "…" [--from <メンバー>]` | ワーカーを別タブ（`worker:<チーム名>/<名前>`）に起動して仕事を頼む（主にメンバーが使う）。`--purpose` は、呼ぶメンバーの `workers:` が名指す目的であること。プロファイルはその組から決まる。目的の外は、呼べる目的を並べて断る。`--from` は、その目的のワーカーを持つメンバーが1人だけなら省ける |
| `hergy ls` | 使えるチーム定義と、チーム定義ごとに起動中のチーム名を一覧する |
| `hergy show <チーム定義>` | 最終的なチーム定義と、各値がどのファイルから来たかを出す |
| `hergy validate` | すべての設定ファイルを検査し、壊れているものを示す。チーム定義は 1 回、ロールの文書も（それを使うチームの数だけではなく）1 回だけ検査する。続けて、規則の件数と、チーム定義ごとのルールとひな形の文字数、ロール定義ごとの文書の文字数を出し、仮置きの基準（それぞれ 3,000 文字）を超えていれば警告する（警告は exit code を変えない） |
| `hergy serve` | 画面をこの機械で配り、URL を出して既定のブラウザで開く（`--port`、既定は 8787。`0` なら空いているポートを OS が選ぶ。`--no-open` なら URL を出すだけで開かない）。出すのはプロファイルとロールの 2 つ。プロファイルごとの名前・kind・引数・環境変数と、それを使っているメンバーとワーカー。メンバーが読む規則の背後にあるロールの文書が並ぶ。127.0.0.1 だけで待ち受け、Ctrl-C で、処理中の応答を待ってから止まる |
| `hergy version` | 入っている hergy のコミットと日時を出す |
| `hergy cheat` | 短いチートシートを出す。`--ai` はエージェント向けの全量を、設定を読まずに英語で出す |

どのコマンドも取るオプション: `-C <ディレクトリ>`（プロジェクトの指定）、`--lang ja`（日本語で表示。既定は英語）、`--json`（`--dry` と併用し、計画を文ではなく JSON で出す）。`apply` / `refresh` / `reprompt` / `hire` は `--team` で対象のチームをチーム名で指定し、`apply` と `refresh` は `--timeout` も取ります。`up` は `--as <チーム名>` で、同じチーム定義を違うチーム名で起動できます（下記）。

`hergy apply` が、動いているチームへの定義の変更を入れる 1 つの操作です。hergy が保存した定義と、メンバーが最後に読んだ prompt を比べ、メンバーごとに反映の仕方（送り直す・起動する・起動し直す・反映できない）を決めます。人は、ずれを見て、反映するメンバーを選ぶだけです。コマンドはメンバーを名指すか、ずれのあるメンバー全員を反映します。画面は同じ計画を `GET /api/apply` で読み、`POST /api/apply` で反映します。`reprompt` と `refresh` は単独の道具として残ります。`reprompt` は初期プロンプトを送り直し（変わったことを前置きに付ける）、`refresh` はメンバーを起動し直します（固まったときなど）。`env` はペインを作ったときに決まるので、`env` を変えたあとは `hergy down` のあと `hergy up` です。反映はそれを断り、メンバーを起動し直しません。

`hergy serve` は、同じ設定を同じ読み方でブラウザに見せる画面です。URL を出すと、この機械の既定のブラウザでその URL を開きます。`--no-open` を付けると URL を出すだけで開きません。ブラウザを起動できなかったときは、URL を手で開けるように stderr に 1 行出して、画面はそのまま動き続けます。この機械のためのもので、127.0.0.1 だけで待ち受け、自分の名前でない要求を断り、書き込みは POST のうち、起動中のプロセスと、そのプロセスが描いたページだけが知るトークンを伴うものに限ります。書き換えるのは、画面が扱うファイル――ロールの文書、2 つの profiles.yaml、チーム定義の 2 つのファイル、グローバルの `config.yaml` の `projects:` だけです。

`hergy serve` は、並べたプロジェクトをまとめて扱う本部になります。グローバルの `config.yaml` の `projects:` にプロジェクトを並べる（絶対パスか `~/…`）と、並べたプロジェクトのチーム定義・ロール・プロファイルが、どのプロジェクトのものかと一緒に、どこで `hergy serve` を起動しても同じに出ます。`projects:` が無ければ、これまでどおり serve を起動したプロジェクトとグローバルの設定だけです。画面の上の［プロジェクト］から開く欄で並べる・外すができ（外しても、そのプロジェクトのファイルは変わりません）、チーム定義の「動き」の列から並べたプロジェクトのチームを起動する・止めるができます。起動するときは herdr のワークスペースを選び（1 つのワークスペースにチームは 1 つ）、結果は `hergy up` / `hergy down` と同じです。動いているチームが保存した定義とずれていると、帯に「反映していない変更 N」が出ます。押すと反映の欄が開き、メンバーごとの反映の仕方と変わったこと、会話が消えるかどうかが出ます。選んだメンバーを反映すると、`hergy apply` と同じ結果になります。進み具合と、起動の途中の確認は、起動のときと同じ欄に出ます。動いているチームは、エージェントが動いていなくても見つかります。チーム名のタブに `<チーム>-<メンバー>` の名前のペインがあれば、そのチームです。活動の画面は並べたプロジェクトを読み、`/api/hq/` の API が同じ読みを返します。

## チーム定義と設定の置き場

| 場所 | 置き場 |
|---|---|
| グローバル | `$XDG_CONFIG_HOME/hergy/`（未設定なら `~/.config/hergy/`） |
| プロジェクト | `<プロジェクト>/.hergy/` |

- チーム定義は `teams/<チーム定義名>/team.yaml` に置きます。同名ならプロジェクトのものが優先です
- `profiles.yaml` とグローバルの `config.yaml` は設定ファイルです。`profiles.yaml` はどちらにも置けます。プロジェクトのチーム定義は、外のものの上にプロジェクトのものを重ねて読み（同名ならプロジェクトが優先）、外のチーム定義は外のものだけを読みます
- グローバルの `config.yaml` に `version: 1` と `lang: ja` を書くと、`--lang` なしでも日本語になります。無ければ `hergy new` が（その実行の表示の言語で）作り、あればそのままにします
- グローバルの `config.yaml` の `projects:` は本部に並べるプロジェクトの一覧です。絶対パスか `~/…` を書き、読むときに展開します。無ければ `hergy serve` は起動したプロジェクトを見せ、空の一覧ならグローバルの設定だけを見せます。相対パスは設定の誤りで、`hergy validate` と `hergy serve` が理由を出します
- `hergy up <チーム定義> --dry` は、メンバーごとのプロンプトと読み込むファイルを表示します

## チーム定義（team.yaml）

```yaml
version: 1              # 必須
mission: "このチームは何のためか"  # 必須。1 行。チームを扱うコマンドの見出しと WebUI が最初に表示する
team: myteam            # 任意。書くならチーム定義名（teams/<チーム定義名>/）と一致させる
cwd: .                  # 作業場所（プロジェクトの直下が基準）
                        # 文書を指す鍵はありません。teams/<チーム定義名>/agreement.yaml（このチーム）と
                        # roles/<ロール名>.yaml を読みます（プロジェクトの .hergy/ が先、
                        # 次に ~/.config/hergy/）
prompt: "…"             # 初期プロンプトのテンプレート（任意）。%{role_doc} と %{docs} は消せません
members:
  - name: lead            # メンバー名（短い名前）。herdr では「<チーム名>-lead」になる
    role: lead          # roles/lead.yaml を読む
    profile: opus       # profiles.yaml のプロファイル名。kind / args / env はそちらに書く
workers:                # 追加してよい「目的 → プロファイル」の組（プロンプトに書くだけで、強制しない）
  - from: lead          # このワーカーを追加してよいメンバー
    purpose: 調査        # ワーカーの目的
    profile: opus       # そのワーカーが使うプロファイル
turns:                  # 誰が誰にターンを渡すか（人間は human と書く）
  - human -> lead
  - lead -> human
```

### 1つのチーム定義から複数のチームを並べて起動する

`--as <チーム名>` を付けると、同じチーム定義を違うチーム名で起動できます。1つの `team.yaml` から2つのチームを並べて動かせます。`--as` を付けなければ、チーム名はチーム定義名（`teams/` の下のディレクトリ名）です。

メンバー名（`members[].name`）は短い名前（`lead`、`builder`）で書きます。hergy が起動するときにチーム名を付けるので、herdr での名前は `<チーム名>-<メンバー名>` になります。`demo` のチーム定義なら `demo-lead`、`demo-builder`、`--as dev2` なら `dev2-lead`、`dev2-builder` です。チーム名は自動で付くので、両方に `lead` がいても herdr で衝突しません。メンバー名に `%{team}` が残っていると止めます（この置換は名前では使わなくなりました）。

チーム名は `[a-z][a-z0-9_-]{0,24}` に、付けた後の `<チーム名>-<メンバー名>` は `[a-z][a-z0-9_-]{0,31}` に一致させてください。hergy は起動中のチームを記録しません。チーム名で指すコマンドは、チームの herdr タブ（`team:<チーム名>@<チーム定義名>`）からチーム定義を見つけるので、`down` / `apply` / `refresh` / `reprompt` / `hire` はどれも動いているチームをチーム名で指します。コマンドでメンバーを指すとき（`apply <メンバー名>`、`refresh <メンバー名>`、`reprompt <メンバー名>`、`hire --from <メンバー名>`）は、書いた短い名前を使います:

```sh
hergy up demo --as alpha            # demo のチーム定義を alpha というチーム名で起動
hergy up demo --as beta             # 同じチーム定義をもう一度 beta として起動
hergy apply --team alpha            # alpha のずれを反映する（変わったことを表示する）
hergy reprompt lead --team alpha    # alpha の lead に、会話を保ったまま送り直す
hergy down alpha                    # alpha のメンバーとワーカーだけを閉じる
```

## profiles.yaml

```yaml
version: 1
profiles:
  opus:
    kind: claude                          # herdr のエージェントの種類
    args: ["--model", "claude-opus-5-5"]  # エージェント CLI にそのまま渡す引数
  dev:
    kind: opencode
    env:                                  # ペインに渡す環境変数
      OPENCODE_CONFIG_CONTENT: '{"model":"…"}'
```

## 初期プロンプトの置換

| 置換 | 中身 |
|---|---|
| `%{team}` / `%{role}` / `%{name}` | チーム名、ロール、メンバーの名前（herdr での名前 `<チーム名>-<メンバー名>`） |
| `%{role_doc}` | ロールの文書 |
| `%{docs}` | `docs` の文書 |
| `%{roster}` | 名簿 |
| `%{herdr}` | herdr での連絡の仕方と、仲間の増やし方（`herdr agent start` ではなく `hergy hire`） |
| `%{turns}` | ターンを渡す相手（team.yaml の `turns:` から） |
| `%{workers}` | ワーカーを追加してよい目的と、そのコマンド（`workers:` がそのメンバーに1つでも書いているとき） |

既定のテンプレートは仮のものです。

- ターンを持っているメンバーの表示（`hergy turn`）

全部、同じ順で走らせます（一覧は `go run ./tools/check -h`）。
